## Критические наблюдения

1. **Оркестрация только частично соответствует ТЗ.** Субагенты действительно работают параллельно, но Root остаётся главным разработчиком и оператором инфраструктуры. Большинство субагентов заняты обзором, audit/review и инвентаризацией.
2. **Строгий §2 остаётся нестабильным.** Помимо длинных status встречаются объявления skills, многократные «runner всё ещё выполняется», типовые планы без нового результата. Это подтверждает необходимость runtime reinforcement/проверки, а не только переписывания policy.
3. **Стагнация критического пути AC2.** Повторные run не привели к acceptance proof. Goal Observer заметил её, но дальнейшая активация не поддерживалась независимо. Работы AC3–AC13 при этом не обязательно являются бесполезными: многие — независимые необходимые AC.
4. **Операционный контекст и ledger.** Несколько срезов отмечают рассогласование `latest_checkpoint` с `current_gap` и `next_action`; отдельные turns заново читают те же policies и начальные сведения. 38 compaction повышают важность компактного канонического operational checkpoint.
5. **Маршрутизатор действительно перезагружен.** В 12:22:56 UTC Root выполнил `ssh -T router reboot` для AC13 UBIFS survival fixture; затем проверил новый `boot_id`, службы, маркер и очистку. В одном из обновлений ledger указано, что reboot кратковременно прервёт трафик. Видимый ответ пользователя разрешал Gate 2 implementation + target qualification; самостоятельное согласование именно перезагрузки в доступном обмене не обнаружено. Для оценки полномочий нужно сверить дизайн Gate 2 и действующие инструкции.
6. **Продолжительность не равна чистому времени работы.** Есть пауза ~80.8 минут между 10:26:52 и 11:47:40 UTC, рядом с ожиданием пользовательского разрешения.
7. **Коммуникации между агентами видны не полностью.** Многие `agent_message` содержат encrypted_content; тексты финальных отчётов субагентов частично доступны в самих child-транскриптах. Не объявлять доказанной полную передачу каждой инструкции и каждого ответа.

## Приоритетные корректировки (по следующему аудиту, не внесены)

- Не останавливать работающую сессию автоматически из-за предварительного аудита. Если её нужно исправить на лету, изменить роль Root: делегировать конкретные независимые реализации/тесты с acceptance, Root оставить integrator/owner live gate.
- Для AC2 переходить к новому live-smoke только после определённой изменённой гипотезы и проверенного доказательства, что изменение адресует фактический failure boundary.
- Goal Observer вызывать повторно после значимого failed live-run / после compaction и по интервалам progress; hook-based механизм пока не установлен.
- При следующем обновлении политик задать deterministic hot reminder для §2 в длительном единственном turn и наблюдать статус его доставки, а не рассчитывать только на стартовое чтение.
- Явно разграничить разрешение на target qualification и разрешение на перезагрузку рабочего роутера.
