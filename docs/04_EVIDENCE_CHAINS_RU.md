# AIR — история проверок и доказательные цепочки

**Зачем:** не повторять провалившиеся гипотезы и не путать наблюдения с интерпретациями. Сведения сведены из исходного handoff и его forensic-отчётов 15–18 октября 2026 г. Сырой 60-МБ архив и JSONL **не входят** в компактный Git-пакет; точные источники, временные отметки и ограничения приведены ниже. Часть ранних аудитов является вторичной интерпретацией, а не независимым повторным чтением каждого события.

**Формат:** `гипотеза → проверка/действие → наблюдение → интерпретация и альтернативы → следующее проверяемое предположение`. Для ретроспективных ситуаций начальная «гипотеза» восстановлена из поставленной задачи и явно отмечена как реконструкция. `SUPPORTED` означает подтверждение *локального наблюдения*, не общей причинности. `UNTESTED` означает, что это ещё план.

## E01. Коррекция Output Policy и активная доставка сообщений

- **Гипотеза:** прямое уточнение поведения во время уже выполняемого turn улучшит human-progress; получение сообщения можно проверить marker.
- **Проверка:** аудит 2026-10-15 в активном Codex-треде; idle probe `DELIVERY_CHECK_20261015_A`, active probe `DELIVERY_CHECK_ACTIVE_20261015_B`; затем узкая style-correction.
- **Наблюдение:** active marker возвращён дословно в том же ходе при `inProgress`. После коррекции появились два содержательных progress, затем рутинные/mixed сообщения; позднее два compliant снова сменились mixed. Первоначальные отправки без marker не имели сопоставимого подтверждения.
- **Вывод:** доставка marker и его использование **доказаны в одной активной сессии**. Устойчивое compliance, causal effect коррекции и доступность *каждой* прошлой инструкции **не доказаны**.
- **Следующий тест AIR:** отделять hook receipt, model-visible canary и поведение; A/B на длинных turns с ограниченным event-based reminder.
- **Источник:** `06_HISTORICAL_REFERENCES/04_PREVIOUS_HANDOFF_2026-10-17/03_EVIDENCE/audits/01_output_policy_runtime_audit.txt`, блоки B/C, marker и message IDs; прежний ZIP `agents-policies-self-contained-handoff-2026-10-18-v2(1).zip`. **Статус:** SUPPORTED для локального marker, MIXED для compliance.

## E02. D1: subagent реально запускался, но содержимое передачи непрозрачно

- **Гипотеза (ретроспективная):** отсутствие plaintext `send_message` в коротком экспорте может означать, что делегирования не было.
- **Проверка:** сопоставили полный `D1_root_complete.jsonl`, child JSONL и UI-скриншот.
- **Наблюдение:** Root JSONL строка 165, 2026-10-16 22:42:18Z: `spawn_agent`, `task_name=ac2_diag_review`; текст поручения зашифрован. В child видны `send_message` 22:44:24Z и 22:45:10Z, payload зашифрован. Финальный child report присутствует. Первый root-progress в строке 39 (22:39:58Z), чтение Caveman-инструкций в строках 1044–1059 (22:56:37–44Z), примерно на 17 минут позже.
- **Вывод:** фактический child spawn подтверждён. Отсутствие plaintext не доказывает отсутствие передачи. Чтение skill через 17 минут не устанавливает, когда модель впервые узнала правило или почему действовала иначе.
- **Следующий тест AIR:** `SubagentStart` canary и роль/область видимости независимым child transcript; отдельное доказательство передачи, без plaintext interception допущений.
- **Источник:** `05_PRIMARY_EVIDENCE/PREVIOUS_D1_SESSIONS/{D1_root_complete.jsonl,D1_ac2_diag_review_complete.jsonl}`, строковые ссылки выше; индекс `06_HISTORICAL_REFERENCES/03_EVIDENCE_RECENT/EVIDENCE_INDEX_RU.md`. **Статус:** SUPPORTED.

## E03. Длинный запуск: файл политики был прочитан, нарушения продолжались

- **Гипотеза (ретроспективная):** уточнение текста `output-policy.md §2` и чтение его в начале достаточно для стабильного progress в длительном запуске.
- **Проверка:** forensic снимка 2026-10-18, окно 03:06:09–12:42:15 UTC (~9ч36м), 64 JSONL: анализ чтений файлов и progress; delta финального архива до 13:03:45Z.
- **Наблюдение:** строгий §2 с лимитом 20 слов был выведен и прочитан в начале, затем повторён ближе к концу. 38 `compacted` в первом снимке, ещё 2 в финальном хвосте. 254 промежуточных сообщения из 264 root assistant messages; 67 из них >40 слов; 110 имеют предложение >20 слов по эвристическому разбиению. Сообщения часто пересказывали действия/планы без нового результата.
- **Вывод:** само чтение текста **не обеспечивает устойчивого соблюдения**. Но по логу нельзя достоверно восстановить модельный контекст каждого ответа, доказать потерю конкретного правила после compaction или установить единственную первопричину. 67/110/254 относятся к **первому снимку**, не к пересчитанному финалу.
- **Следующий тест AIR:** canary before/after compaction + сравнительные progress fixtures; не обещать enforcement до данных.
- **Источник:** `03_EVIDENCE/SUMMARY_9H_RU.md`, `03_EVIDENCE/DELTA_FINAL_RU.md`, финальный 7z `05_PRIMARY_EVIDENCE/FINAL_10H_SOURCE/прогона-закончен.7z`, SHA256 `bc95e4a1d7460963f1ed836c75f9ecd51c5597875ee76d1e48deb0c492679239` в исходном архиве. **Статус:** SUPPORTED по подсчитанным событиям; CAUSAL UNKNOWN.

## E04. Root как исполнитель при действительных субагентах

- **Гипотеза (ретроспективная):** наличие субагентов означает, что Root главным образом координирует работу.
- **Проверка:** частотный подсчёт tool actions по основному и дочерним transcript в ~9ч36м снимке.
- **Наблюдение:** 29 `spawn_agent`, 68 `followup_task`, 66 `list_agents`, 66 `wait_agent`. При этом Root инициировал 431 `apply_patch` вызов против 45 у содержательных children, то есть ~90,5% попыток patch. Это не числа уникальных успешных изменений.
- **Вывод:** Root оставался главным инициатором изменений несмотря на делегирование. Для AIR **это требование к агенту-исполнителю проекта**, а не доказанная функция самого plugin.
- **Следующий тест/действие:** в ТЗ назначить субагентам независимые worktrees/files и acceptance; Root интегрирует. Отдельный будущий Root orchestration workstream.
- **Источник:** `03_EVIDENCE/SUMMARY_9H_RU.md`. **Статус:** SUPPORTED для структуры действий.

## E05. Goal Observer помог диагностике, но не обеспечил повторное наблюдение

- **Гипотеза (ретроспективная):** независимый наблюдатель автоматически удерживает прогресс по AC.
- **Проверка:** по событиям основного JSONL отследили вызов goal observer в 05:44–05:46 UTC.
- **Наблюдение:** обнаружена стагнация AC2 (`stagnation=true`, низкий progress). До конца следующего ~7-часового окна повторного вызова в архиве нет. AC2 остался `NOT_DONE` при остановке пользователем. Конкретные технические замечания независимых агентов к другим AC были полезны.
- **Вывод:** способность найти проблему локально подтверждена; периодическое самостоятельное включение не установлено. Данный случай не следует превращать в реализацию Goal Observer внутри первой версии AIR.
- **Следующая гипотеза:** в будущем observer с подтверждённым event trigger, отдельным acceptance и собственной source-of-truth policy.
- **Источник:** `03_EVIDENCE/SUMMARY_9H_RU.md`, `03_EVIDENCE/DELTA_FINAL_RU.md`. **Статус:** SUPPORTED для единичного вызова; DEFERRED.

## E06. Среда Windows и выполнение вспомогательных scripts

- **Гипотеза:** имеющийся PowerShell helper запускается стандартным способом в агентской среде.
- **Проверка:** исторический тест `docker-operations` (не AIR) с обычным `powershell.exe` и отдельно процессно ограниченным `-ExecutionPolicy Bypass`; сравнение sandbox/interactive environment.
- **Наблюдение:** `AuthorizationManager check failed` при обычном запуске. Process-only bypass позволил вызвать helper, но в sandbox Engine не стартовал; вне sandbox запуск удалось завершить.
- **Вывод:** interpreter/permissions/GUI session являются реальными факторами тестирования Windows lifecycle. **Не переносить обход политики исполнения как обязательный рецепт AIR**.
- **Следующий тест AIR:** isolated Node/PowerShell invocation в настоящем Codex Desktop, quoting, UTF-8, path, trust, rollback.
- **Источник:** `06_HISTORICAL_REFERENCES/04_PREVIOUS_HANDOFF_2026-10-17/03_EVIDENCE/short_tests/03_ssh_docker_trial.txt`, ближе к концу. **Статус:** SUPPORTED для чужого helper; AIR NOT TESTED.

## E07. Повторные чтения и compaction в 24-часовом текстовом экспорте

- **Гипотеза (ретроспективная):** частые чтения policy/skills отражают устойчивую маршрутизацию и нужный рефреш.
- **Проверка:** вторичный аудит текстового экспорта 24h, а не полных tool payloads.
- **Наблюдение:** 92 упоминания compaction; 88 явных чтений `SKILL.md` для 16 skills; неоднократное повторное чтение политик и ошибочные повторные сетевые команды. Реальное количество успешных операций и стоимость в токенах не восстановлены.
- **Вывод:** повторные чтения и потери эффективности видимы; **не доказано**, какие чтения были лишними, а какие нужны после compaction/изменений. Native discovery не следует замещать реестром AIR.
- **Следующий тест AIR:** keyed source cache, native/AIR owner map, верифицируемые изменения в delivery/повторах.
- **Источник:** `06_HISTORICAL_REFERENCES/04_PREVIOUS_HANDOFF_2026-10-17/03_EVIDENCE/audits/03_24h_forensic_secondary_report.txt` (вторичный текстовый анализ). **Статус:** SECONDARY OBSERVATION.

## E08. Гипотеза: `UserPromptSubmit` даст напоминания внутри длительного хода

- **Исходная идея:** использовать hook user prompt как периодический hot reinforcement §2.
- **Проверка:** контракты событий в прежнем handoff, без фактического AIR plugin E2E.
- **Наблюдение:** `UserPromptSubmit` событие нового user prompt, не вызов после каждого внутреннего шага/инструмента; внутри single long turn механизм не срабатывает повторно сам по себе.
- **Вывод:** подходит для new-turn extraction/hot, не для intra-turn reminder. `PostToolUse` и иные поддерживаемые события следует проверять отдельно; их покрытие не доказано.
- **Следующий тест AIR:** hook receipts + state only vs hot bounded; event-based intra-turn smoke.
- **Источник:** `02_DECISIONS/ARCHITECTURE_DECISIONS_RU.md` и `01_CURRENT/AGENTS_POLICIES_TZ_RU.md` предыдущего архива; это **контрактный вывод**, не AIR эксперимент. **Статус:** CONTRACT-LEVEL.

## E09. Откуда взялась новая структурированная архитектура

- **Гипотеза:** произвольный Markdown и LLM-выделение фрагментов усложняют stable identities, validation и caches.
- **Проверка:** архитектурная дискуссия Sol-5.6/Sol-6: от BDD и `subject/predicate/target` пришли к разделению Format Schema / Vocabulary / Policy / Rule, свободным namespace vocabularies, `description` как NL, `applies_if` как формальным условиям.
- **Наблюдение:** решение **согласовано концептуально**, но schema не реализована, сравнение разных symbols не доказано, `permit`/unknown facts остаются открыты.
- **Вывод:** это **design rationale**, а не эксперимент на Windows или измеренный эффект.
- **Следующая гипотеза:** прототип schema + фикстуры + cross-vocabulary resolution против набора контрпримеров; только затем cutover live policies.
- **Источник:** текущая архитектура/ADR и диалог, перенесённый в данный пакет. **Статус:** DESIGN / UNTESTED.

## E10. Где закончился исходный большой прогон

- **Наблюдение:** финальный forensic delta сопоставил байтовый префикс 95 787 063 / 99 700 261 байт основного JSONL и 1261 новых event records; финал UTC 2026-10-18 13:03:45.972, `PAUSED_BY_USER`, AC2 `NOT_DONE`.
- **Значение для AIR:** этот прогон является **источником наблюдений поведения агентов**, а не поводом продолжить инфраструктурные AC. Последний статус включён только для честного происхождения evidence.
- **Источник:** `03_EVIDENCE/DELTA_FINAL_RU.md` старого архива. **Статус:** SECONDARY FORENSIC CONFIRMATION.

## Что не исследовали

1. Ни одного controlled E2E AIR hook injection в установленном Codex Desktop.
2. Никакой надёжной оценки потери policy после конкретного compaction.
3. Никакой доказанной user > developer self-delegation в реальном host.
4. Никаких измерений недорогого LLM-resolver внутри sync hook или после cache miss.
5. Никакой независимой валидации cross-vocabulary candidate coverage и Session Directives persistence.

Эти пункты превращаются в **обязательные experiments + IF/THEN gates** в [`05_EXPERIMENTAL_TZ_RU.md`](05_EXPERIMENTAL_TZ_RU.md).

## Provenance и очистка

Прежний большой handoff: `agents-policies-self-contained-handoff-2026-10-18-v2(1).zip`; исходные пути сохранены в каждом case. Содержимое первичных журналов в этом компактном репозитории удалено из рабочего дерева, потому что для продолжения разработки AIR достаточно указанных наблюдений и воспроизводимых экспериментов. Оригинальные JSONL остаются только у владельца исходного архива. Чувствительные raw worker diagnostics, host paths и содержимое незашифрованных пользовательских запросов сюда не переносятся. Для спорного исторического утверждения открыть соответствующий original file **точечно**, обозначить scope reread и обновить эту evidence chain.
