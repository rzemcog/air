# Визуальное чтение документации AIR

Документы AIR остаются Markdown. Их визуальная оболочка подключается локальными файлами CSS/JS через официально документированные директивы [MdStyled](https://github.com/OsamaAbuSitta/MDStyled).

## Открытие в VS Code

1. Откройте корень репозитория AIR в VS Code.
2. Установите расширение **MdStyled** (`OAS.mdstyled`).
3. Откройте `README.md` или документ в `docs/` и вызовите **MdStyled: Open Preview** / **Open Preview to Side**.
4. Для встроенной интерактивности MdStyled можно дополнительно использовать `interactive-dark` или `interactive-light`. Файлы проекта подключают собственную тему автоматически, без копирования шаблона.

## Что поддерживается

- **CSS:** типографика, респонсивные карточки, таблицы, сценарные ветви и контрастные статусы.
- **JavaScript:** подсветка выбранной ветви в диаграммах; все ветви видимы без JavaScript.
- **HTML:** схемы сохраняют текст и порядок исполнения при обычном Markdown/HTML просмотре. В GitHub видны блоки без фирменной стилизации и без интерактивности.
- **Offline:** скрипты, стили и диаграммы берутся из репозитория, без CDN и внешней телеметрии.

## Архитектура оформления

```text
AIR/
  README.md                            # entrypoint
  docs/
    air.css                             # общая тема
    air.js                              # необязательная интерактивность
    00_RENDER_TEST_RU.md                # самодиагностика CSS/JS
    01_ARCHITECTURE_RU.md              # две HTML-схемы
    05_EXPERIMENTAL_TZ_RU.md           # схема исследовательского цикла
    10_IMPLEMENTATION_DRAFT_TZ_RU.md   # карта зависимостей
```

В начале каждого Markdown-документа подключены пути относительно самого документа:

```md
<!-- @style: ./air.css -->
<!-- @script: ./air.js -->
<!-- @page: air-docs -->
```

В корневом README относительный путь начинается с `./docs/`.

## Границы

Этот слой изменяет только внешний вид документов. Он не утверждает открытые ADR, не меняет текст политик, не влияет на исполняющие hooks AIR, не требует сетевых библиотек. Если установленный релиз расширения изменит правила обработки raw HTML, содержательные разделы Markdown остаются доступными как текст; внешнее оформление потребует адаптации.

## Если схемы отображаются без CSS

В Markdown встроенных CSS fallback больше нет: это маскировало исходную проблему. Используется **один** документированный способ подключения: `@style`/`@script` с путями относительно текущего `.md`. Структура диаграмм сохранена в HTML, оформление полностью вынесено в `air.css`.

1. Открой [`00_RENDER_TEST_RU.md`](00_RENDER_TEST_RU.md) в MdStyled Preview.
2. Проверь внешнюю зелёную карточку и computed CSS.
3. Если CSS не загрузился, открой Developer Tools и сравни длину CSS в сообщении `[MdStyled] Preview loaded, CSS length:`; это показывает проблему **конкретного рендера**, а не проблему обычного браузера.
4. Учитывай, что MDStyled удаляет произвольные `data-*` и некоторые HTML-атрибуты при sanitization. Поэтому интерактивные ветви AIR используют разрешённые `class`, `id`, `href` и `<a>` вместо `data-air-*` и `<button>`.

Важное ограничение: после изменений нужен тест именно в установленной версии MDStyled; испытание в Chromium не подтверждает её поведение.

Подробный разбор API расширения: [`MDSTYLED_INTEGRATION_NOTES_RU.md`](MDSTYLED_INTEGRATION_NOTES_RU.md).
