# Документация AIR в MdStyled

## Область применения

Применяй этот skill при создании и изменении Markdown-документов AIR, особенно схем, таблиц, карточек, визуальной темы и интерактивности. Изменения представления не должны менять принятые ADR, статусы экспериментов и нормативные положения.

## Контракт оформления

- Общая тема: `docs/air.css`; интерактивность: `docs/air.js`. Все документы `docs/*.md` объявляют `<!-- @style: ./air.css -->` и `<!-- @script: ./air.js -->`, а корневой `README.md` использует `./docs/air.css` и `./docs/air.js`.
- Пути разрешаются MDStyled относительно файла Markdown. Не создавай дублирующие конфигурации и не добавляй в Markdown ручные `<style>`, `style="..."` или встраиваемые копии CSS/JS.
- Для просмотра документа с темой AIR используй **Open with MdStyled** или **MdStyled: Open Preview**. `MdStyled Edit` подменяет ассеты документа встроенной темой редактирования; редактируй Markdown непосредственно в VS Code при открытом обычном предпросмотре.
- HTML проходит через sanitizer MDStyled: `class`, `id`, `href` доступны; пользовательские `data-*` и `button` не считай поддержанными. Классы и ID проекта начинаются с `air-`.
- Основные тексты, заголовки, ссылки и таблицы оформляй Markdown. HTML используй для композиции схем. Важный смысл и подписи сохраняй доступными при отключённом JS.
- Для интерактивных схем используй ссылки `a.air-flow-filter`, классы ветвей `air-lane--...` и делегирование событий в `air.js`. Обеспечь клавиатурную доступность и адаптацию для узкой панели VS Code.
- Не добавляй CDN, внешние скрипты и тяжёлые графические зависимости ради оформления.

## Порядок изменений

1. Найди затрагиваемый Markdown/HTML и соответствующие селекторы в `docs/air.css` и обработчики в `docs/air.js`.
2. Внеси минимальные правки без изменения архитектурного смысла, проверь отсутствие обрезания текста и корректность схем на ширине около 560 px.
3. Открой изменённые документы командой **Open with MdStyled**, проверь читабельность, адаптивность и работу необязательных переключателей. Проверка в другом браузере не подтверждает поведение расширения VS Code.
4. Запусти `python tools/verify_package.py`, затем `git diff --check`. Обновляй `SHA256SUMS` после окончательных изменений файлов.
5. Зафиксируй результат в Git, не меняя Shared Policy или незакрытые архитектурные решения в ходе визуальной правки.

## Приёмка

Документы читаемы как Markdown без выполнения JS; CSS/JS вынесены в общие файлы; локальные ссылки работают; отсутствуют ссылки на несуществующие локальные материалы; проверка пакета пройдена. Непроверенный в реальном VS Code внешний вид не отмечай как подтверждённый.
